# 삭제 확인 이력의 재점검

인스턴스 목록은 30초마다 전체 페이지를 조회하며 실행 중인 문제와 정리 대기 자원은 매번 Runtime에 확인한다
Scheduler가 종료 상태이고 인증된 Runtime 응답의 식별자·작업 대상·실행 자원 ID·관측 시각이 일치하며 phase가 TERMINATED일 때만 삭제 확인 이력을 5분간 재사용한다

재사용한 결과의 runtime_observed_at과 deletion_verified_at은 원래 확인 시각을 유지한다
deletion_recheck_at은 해당 시각에서 5분 뒤이며 화면에 두 시각을 표시한다
이 결과는 삭제된 자원의 과거 확인 기록이며 현재 문제 기능이 정상이라는 뜻이 아니다

다음 경우에는 즉시 다시 조회한다

- Scheduler 상태·인스턴스·문제·대상·실행 자원 ID·만료 시각 변경
- Runtime 관리 주소·토큰 환경변수 이름·실제 인증 값 변경
- 5분 재확인 기한 도달
- 프로세스 재시작 또는 목록에서 제거됐다 다시 나타난 기록

전체 목록 조회 실패와 감시 비활성화는 보관된 삭제 확인을 비운다
재점검이 실패하면 예전 삭제 확인으로 되돌아가지 않고 미확인으로 표시한다
종료된 자원이 다시 나타나면 다음 재점검에서 TERMINAL_RESOURCE_PRESENT로 표시한다
따라서 삭제된 이력에 대한 자원 재등장 확인에는 최대 5분의 간격이 있으며 실행 중인 문제의 점검 주기는 유지된다

감시 수집 자체가 멈추면 기존 목록 유효기한을 적용해 STALE로 바꾸며 재사용한 삭제 확인도 정상 표시를 유지하지 않는다
새 주소를 탐색하거나 서비스 URL에 접속하지 않으며 Runtime은 등록된 HTTPS 관리 경로에서만 읽는다
